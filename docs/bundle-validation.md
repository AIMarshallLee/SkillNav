# 单入口能力集成验收

日期：2026-09-09。软件仍为 0.1.0 开发候选；本轮扩展基础审查与创建能力，未创建
正式 Release。目标是让用户只说任务，不必先查找几个辅助技能的入口。

## 已实现的范围

| 能力 | 实现与边界 |
| --- | --- |
| 直接完成／执行 | 保留简单任务直接完成、有需要才发现下游、真实交接和产物检查 |
| 技能搜索 | 现有有界元数据查询；外部查找由宿主授权工具完成，不自建市场或远程索引 |
| 基础风险审查 | 新增 `review_skill.py` 与按需审查指引；检查指定包的本地静态信号，报告位置、覆盖及未读部分，不执行候选 |
| 创建与验证 | 新增 `create_skill.py` 与按需创建指引；从完整规格创建指令技能，结构验证后由宿主进行真实试用，安装分开处理 |
| 可选偏好 | 保留默认关闭的作用域记忆；创建技能不构成记忆同意 |

独立技能包从 10 个文件增为 14 个。入口由 206 行／13564 字节缩为
97 行／6592 字节；审查和创建细节按需读取。这里是源文件行数和 UTF-8 字节数，
不代表模型 Token 或整体任务成本下降。四个新增文件是两个参考工作流和两个辅助
脚本；基础能力不要求安装其他搜索、审查或创建技能。

现有宿主工具和账户仍是实际执行条件。创建器只是指令包写入和有限结构验证工具，
不是万能代码生成器；脚本型资源由宿主在授权草稿中编写、审查和实际测试。

## 自动化与独立复核

全量 **110 项测试通过**；这只是脚本与文件契约检查，不代表行为通过率。
skill-creator 格式检查与 Git 差异检查通过。新增测试覆盖普通文件/目录、软硬链接、
特殊文件、读取上限、正文和规格大小、重复 JSON 字段、无效 Unicode、控制字符、
占位符、调用策略、链接越界、已有目录拒绝及失败清理。

独立代理的只读安全复核发现并复验修复了这些问题：

- 审查器最初允许目录形式的 `SKILL.md` 通过，并允许过大的调用方读取上限。
  已限制为单一普通入口文件，并设置硬上限。
- 创建器最初存在祖先链接／硬链接、超长正文、Windows 绝对路径、特殊字符和重复
  字段等输入边界缺口；已补充检查与回归。
- 过宽的占位符规则会误拒绝“Find TODO comments”，收窄后又漏掉纯 TODO 字段；
  最终按字段识别未填写占位符，同时保留正常任务描述。

复核在规定的稳定本地目录、静态检查与草稿创建范围内未发现剩余阻断项。
这不是第三方认证，也不证明所有恶意代码、平台或宿主行为都已覆盖。

## 真实单入口任务

测试准备器 [prepare_bundle_eval.py](../tests/prepare_bundle_eval.py) 只创建合成输入和
候选，冻结原始文件哈希，不预置成功结果。每项使用新的 Codex CLI 临时会话，
只引用 `$skillnav`，不提供其安装路径；测试明确允许读取安装包和运行其自带脚本。
禁止额外搜索／审查／创建技能、长期记忆、真实外部动作及候选安装。
任务执行沿用宿主默认模型和推理设置，未指定覆盖，也未统一采集有效模型或 Token。

实际结果及工具证据见 [单入口检查摘要](evidence/bundle/host-checks.json)。
四个任务及一次复用测试的 CLI 进程均退出 0，原始输入／技能源文件哈希保留。
本次没有要求用户转到另一个辅助技能入口，也没有观察到额外搜索、审查或创建技能
被激活。候选启用状态和获准文件读取方式由测试宿主明确提供，不能外推用户全机状态。

| 场景 | 实际结果 | 可核对证据 |
| --- | --- | --- |
| 简单任务 | 一次命令计算、写入并读回 71；无目录扫描或下游加载 | 原始 CLI 命令与文件检查 |
| 搜索与交付 | 从 362 个合成候选中找到两项项目规范，实际运行发票脚本，再应用通知格式 | [核对结果](examples/bundle-handoff/result.json)、[通知草稿](examples/bundle-handoff/notice.md)：17.50、INV-17 |
| 只读审查 | 识别指令注入、凭据读取、网络外发及任务功能缺失；未运行候选，也未读取凭据文件 | [脱敏报告](examples/bundle-review/review.md)、[静态输出](examples/bundle-review/review-static.json)；原始命令另经审阅 |
| 创建与试用 | 实际运行包内创建器、静态审查器与结构校验器；写出完整技能，应用其规则生成样例、边界及空输入产物 | [生成的技能](examples/bundle-create/team-weekly-brief/SKILL.md)、[样例周报](examples/bundle-create/sample-weekly-brief.md) |
| 新会话复用 | 将生成技能原样复制到隔离测试目录，新会话只收到不同输入与任务，扫描、读取并应用该技能 | [新输入](examples/bundle-reuse/input.md)、[实际周报](examples/bundle-reuse/report.md)：未知前缀保留、内部行排除、空章节正确 |

创建器所在会话自测了样例及两个边界输入；主任务另核对实际样例输出，并使用上表
的新会话验证不同输入。生成技能没有安装进真实用户目录，测试目录的副本也不是
商业使用或用户验收。更新的是用户已授权安装的 SkillNav 本身，14 个文件均完成
源文件哈希读回，旧包有本地备份。

文件检查与真实命令审阅分开：
[verify_bundle_eval.py](../tests/verify_bundle_eval.py) 只检查文件契约、原始输入哈希和
合成执行标记，明确不验证审查语义或调用行为。审查文件存在、执行标记不存在，
都不能单独证明没有执行过候选代码；必须另看完整工具记录。

## 保留的试验问题

- 搜索任务有一次未命中 AGENTS.md 的查询；审查和创建任务各查询了一次不存在的
  `.agents/skills` 目录。这些多余查询没有阻断交付，但本轮不宣称步骤最少或耗时下降。
  审查器自身的 exit 1 表示发现风险信号／覆盖不完整，是约定状态，不是崩溃。
- 首版文件检查器把 `trial.md` 误当作周报正文；任务实际要求它是“试用报告”。
  保留 [首次检查](evidence/bundle/artifact-checks-first.json) 后，改为核对报告链接的
  实际周报，并增加回归。没有重写任务输出，也没有修改周报内容标准；
  [修正后的检查](evidence/bundle/artifact-checks.json) 通过。
- 模型生成的报告出现了把模型源码审阅称为“人工”的措辞。公开副本明确标注了
  归属更正，原文哈希保留；审查指引追加了一句不得冒称人工审查的约束。该句在
  宿主试验后增加并读回，没有单独再次做行为测试；可执行代码未因此改变。

[试验时包哈希](evidence/bundle/tested-package-files.json) 和
[最终包哈希](evidence/bundle/package-files.json) 明确保留了这一个参考文档变化。

## 验证边界与复现

审查器不会返回“已认证安全”。默认最多读取 128 个文本文件、单文件 128 KiB、
总量 1 MiB，受目录深度和枚举量限制；被跳过的资源和依赖要明确列出。
指纹只覆盖实际读取的文本。静态模式可能漏掉混淆、运行时行为和远程依赖；否定
句及文档示例也可能命中，需要结合上下文判断。

创建器只支持其生成包格式的结构检查及常见内联本地 Markdown 链接，无法替代
完整 Markdown 解析、脚本审查或行为验收。新技能须在授权场景试用；不能把“结构
通过”“样例通过”“安装成功”“用户认可”合并成一个通过标记。

运行全量脚本测试：

```sh
.venv/bin/python -m unittest discover -s tests -v
```

准备新的合成任务，分别用真实新会话执行 `requests.json`，之后检查实际产物：

```sh
.venv/bin/python tests/prepare_bundle_eval.py
.venv/bin/python tests/verify_bundle_eval.py /path/to/generated-workspace
```

原始宿主事件、安装备份与本地测试路径留在忽略目录；公开证据只包含合成产物和
脱敏检查摘要。未验证真实用户采用、跨平台效果、桌面菜单刷新、生产业务效果，
以及相对原生 Codex 的普遍准确率、速度或成本优势。
